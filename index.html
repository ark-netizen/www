idealwhy?
ideal우리가 도달하고 싶은 이상적인 모습. 좋아 보이는 답.
why?그 답에서 한 번 더 묻는 질문. 왜 필요한지, 왜 이 방식이어야 하는지.

idealwhy는 이상적인 것에서 멈추지 않고,
“왜?”라는 질문으로 한 발 더 나아가기 위한 이름입니다.

좋은 아이디어는 답처럼 보일 수 있습니다. idealwhy는 무엇이 좋아 보이는지보다 왜 필요한지 묻고, 질문이 선명해지면 직접 만들어봅니다.

01 / THE NAME

ideal은 방향이고,
why?는 그 방향을 검증하는 질문입니다.

ideal + why?좋아 보이는 답 → 이유를 묻는 질문 → 실제로 작동하는 형태
01

좋아 보인다고 끝내지 않습니다.

‘이게 있으면 좋겠다’는 감각은 출발점입니다. 누구에게, 어떤 순간에, 왜 필요한지를 다시 묻습니다.

02

문제를 질문의 형태로 바꿉니다.

해결책을 먼저 정해두기보다 기존 방식이 왜 불편한지, 무엇이 빠져 있는지를 분해합니다.

03

질문이 선명해지면 만들어봅니다.

기획서에서 끝나지 않고 작게라도 동작하는 형태로 구현해 실제 경험에서 확인합니다.

02 / BELIEF

좋은 답을 만드는 것보다,
좋은 질문을 끝까지 밀어붙이는 것.

01문제와 해결책 사이에 “왜?”를 한 번 더 넣습니다.
02아이디어보다 사용자의 행동과 맥락을 먼저 봅니다.
03설명만 가능한 아이디어보다 경험할 수 있는 형태를 선호합니다.
04완벽한 첫 답보다 질문하면서 고도화되는 답을 만듭니다.
03 / QUESTIONS → THINGS

질문은 결국
무언가의 형태가 됩니다.

결과물의 목록보다, 어떤 질문이 어떤 경험과 제품으로 이어졌는지를 보여줍니다.

출근, 관계별 메시지, 영어 답변, AI 후속 대화, 퇴근 리포트까지 하나의 업무 흐름으로 구현했습니다.

모든 고민에 답이 필요한 건 아니었습니다.

“어떤 조언을 건넬까?”가 아니라 “사용자가 스스로 고민을 내려놓는 순간을 어떻게 경험하게 할까?”로 바꿨습니다.
